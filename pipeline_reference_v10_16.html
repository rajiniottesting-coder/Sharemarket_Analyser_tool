v10.16 Option B summary

Five valuation fields (PE, PB, PS, EV/EBITDA, PEG) display "—" when raw values exceed thresholds (500 for PE/PB/PS/EV; 50 for PEG). The DB stores numeric clamps for scoring hygiene, but the display layer converts to honest "—". The fundamental_score has new neutrality logic: if pe_num ≥ 500: pass (no penalty), preventing the spurious "expensive" tag on stocks with near-zero EPS. Defensive coerce helpers added to v7_analysis_engine, bs_engine, and excel_generator to handle "—" safely. 198/198 integration tests pass.

v10.13 prior-analysis enrichment (enables O4 + O5)

Stage 3 reads latest_analysis_results table at startup via get_prior_analysis_map(). This populates last_claude_score and days_since_analysis columns, activating O4/O5 overrides. On the first-ever pipeline run the table is empty, so both overrides are no-ops — behavior matches pre-v10.13 (O1/O2/O3 only).

Stage progression — exact column lifecycle

After Stage 1: bhav columns only — symbol, close, prev_close, volume, turnover, delivery_pct, sc_group, exchange_tag
After Stage 2: + stage2_score (0-35), + cap_category (proxy from turnover)
After Stage 3: + priority_score (0-100), + override flags (o1-o5), + days_since_analysis, + last_claude_score
After yfinance enrichment: + 86 fundamental fields (pe, pb, roe, de_ratio, etc.)
After Section 6: + fundamental_score, + safety_score, + sentiment_score, + composite_score, + verdict, + label, + storm_score, + forensic_adj

Quick-pick labels are SEPARATE from verdict

stock["verdict"] (BUY/WATCHLIST/NEUTRAL/OVERVALUED/AVOID) and stock["label"] (DEEP VALUE / EARLY MOVER / etc.) are independent outputs assigned by different functions. The verdict drives Excel cell color; the label powers Gold-sheet sorting.
